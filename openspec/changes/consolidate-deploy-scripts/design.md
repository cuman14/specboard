## Context

The deployment pipeline consists of:
- `.release-it.json` — release-it configuration (version bump, git tag, GitHub Release, changelog)
- `.github/workflows/release.yml` — 3-job CI: version/tag → build matrix → update manifests
- `scripts/sync-versions.js` — called by release-it `after:bump` hook to sync version across Cargo.toml, tauri.conf.json, scoop, homebrew
- `scripts/update-sha256.js` — called by workflow Job 3 to update scoop/homebrew SHA256 from CI artifacts
- `scripts/update-sha256-from-artifacts.js` — dead code, never invoked, incompatible format
- `DEPLOYMENT_MODERNIZATION.md` — abandoned plan to migrate to Changesets, never executed
- `AGENTS.md` — references the dead script name

Current issues: dead code, stale docs, fragile regex for Homebrew SHA256, `releaseBody` in tauri-action overwrites release-it's changelog, `ubuntu-22.04` aging, unpinned pnpm version, scripts scattered at root of `scripts/`.

## Goals / Non-Goals

**Goals:**
- All deployment scripts live in `scripts/deploy/` — single discoverable location
- Zero dead code or stale references in the repo
- Homebrew SHA256 update is robust against formula structure changes
- GitHub Releases preserve the full changelog generated by release-it
- CI uses current Ubuntu LTS and pinned pnpm version
- No runtime or user-facing behavior changes

**Non-Goals:**
- No changes to release-it configuration logic or hook behavior
- No changes to the 3-job workflow structure or dependency graph
- No changes to Tauri build configuration or installer formats
- No migration to Changesets or other versioning tools

## Decisions

### 1. Scripts directory structure
**Decision:** Move `sync-versions.js` and `update-sha256.js` into `scripts/deploy/`. Keep them as separate files rather than merging.

**Rationale:** A dedicated `deploy/` subdirectory groups all deployment-related scripts together while keeping each script focused on a single responsibility. Merging into one file would create a large, hard-to-maintain script.

**Alternatives considered:**
- Merge into single `scripts/deploy.js` with subcommands — too complex, harder to maintain
- Keep at root of `scripts/` — no consolidation benefit

### 2. Homebrew SHA256 regex approach
**Decision:** Replace the naive `sha256 "[^"]+"` regex with a context-aware pattern that targets the SHA256 inside the `on_arm` block.

**Rationale:** The current regex matches the first `sha256 "..."` in the file. If a `bottle` block is added with its own SHA256 entries before the `on_arm` block, the wrong value would be updated. The new pattern anchors to the `on_arm do` context.

**Alternatives considered:**
- Parse the Ruby formula with a proper parser — overkill for a simple replacement
- Use line-number-based replacement — fragile if formula structure changes

### 3. Remove `releaseBody` from tauri-action
**Decision:** Remove the `releaseBody` parameter from tauri-action config.

**Rationale:** release-it creates the GitHub Release with a full changelog as the body. Tauri-action's `releaseBody: "See CHANGELOG.md for details."` overwrites this. Removing the parameter lets tauri-action only upload assets without modifying the body.

**Alternatives considered:**
- Pass release-it's changelog to tauri-action — complex, requires inter-job communication
- Keep current behavior — loses changelog in Releases

### 4. Pin pnpm to v9
**Decision:** Use `npm install -g pnpm@9` instead of `npm install -g pnpm`.

**Rationale:** pnpm v11 is already installed locally, but CI should use a pinned major version to avoid unexpected breaking changes. v9 is the current LTS line and matches the project's tested configuration.

**Alternatives considered:**
- Pin to exact version (e.g., pnpm@9.15.0) — too strict, blocks security patches
- Use pnpm@latest — current behavior, risk of breaking changes

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| Path change breaks local dev scripts that reference old paths | Update AGENTS.md; paths are only used by CI and release-it hooks |
| Homebrew regex still fragile if formula adds `on_intel` block | The new regex is scoped to `on_arm` only; if Intel support is added, the script will need updating anyway |
| Removing `releaseBody` might cause tauri-action to leave body empty if release doesn't exist | Tauri-action only uploads to existing releases (from release-it); if release missing, the build fails anyway |
| `ubuntu-24.04` might have different system dependency names | Tauri v2 dependencies are the same across Ubuntu LTS versions; verify on first run |

## Migration Plan

1. Create `scripts/deploy/` directory
2. Move `sync-versions.js` and `update-sha256.js` to `scripts/deploy/`
3. Update `.release-it.json` hook path
4. Update `release.yml` script path and apply other improvements
5. Update `AGENTS.md` references
6. Delete dead files
7. Test: push a commit to main and verify the workflow runs correctly

**Rollback:** Revert the commit. Since this is an infrastructure change with no data migration, rollback is a simple git revert.
