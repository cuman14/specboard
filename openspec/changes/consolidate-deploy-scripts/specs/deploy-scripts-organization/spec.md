## ADDED Requirements

### Requirement: Deployment scripts SHALL be organized under scripts/deploy/
All scripts related to version synchronization, SHA256 manifest updates, and CI deployment helpers SHALL reside in the `scripts/deploy/` directory. The root `scripts/` directory SHALL NOT contain deployment-related scripts.

#### Scenario: New developer locates deploy scripts
- **WHEN** a developer looks in the `scripts/` directory
- **THEN** they find a `deploy/` subdirectory containing all deployment-related scripts

#### Scenario: No deploy scripts exist at scripts/ root
- **WHEN** listing files in `scripts/`
- **THEN** no deployment-related scripts (sync-versions.js, update-sha256.js) appear at that level

### Requirement: Dead deployment code SHALL be removed
The `scripts/update-sha256-from-artifacts.js` file SHALL be deleted as it is never invoked by any workflow or hook and uses an incompatible artifact format. The `DEPLOYMENT_MODERNIZATION.md` document SHALL be deleted as it describes an abandoned migration plan.

#### Scenario: Dead script is absent from repository
- **WHEN** searching for `update-sha256-from-artifacts.js` in the repository
- **THEN** the file does not exist

#### Scenario: Stale plan document is absent from repository
- **WHEN** searching for `DEPLOYMENT_MODERNIZATION.md` in the repository
- **THEN** the file does not exist

### Requirement: AGENTS.md SHALL reference correct script paths
The `AGENTS.md` documentation SHALL reference `scripts/deploy/update-sha256.js` (not the dead script name) and `scripts/deploy/sync-versions.js` in the Deployment & Versioning section.

#### Scenario: AGENTS.md lists correct script names
- **WHEN** reading the Deployment & Versioning section of AGENTS.md
- **THEN** it references `sync-versions.js` and `update-sha256.js` under `scripts/deploy/`

### Requirement: Homebrew SHA256 update SHALL target the on_arm block specifically
The `update-sha256.js` script SHALL update the SHA256 hash within the `on_arm do` block of the Homebrew formula, not the first `sha256` occurrence in the file. The URL within the same `on_arm` block SHALL also be updated.

#### Scenario: SHA256 is updated inside on_arm block
- **WHEN** `update-sha256.js` runs against a Homebrew formula with an `on_arm do` block
- **THEN** only the SHA256 inside that block is updated, leaving any other sha256 entries untouched

#### Scenario: URL is updated inside on_arm block
- **WHEN** `update-sha256.js` runs against a Homebrew formula
- **THEN** the download URL inside the `on_arm do` block is updated to the new release URL

### Requirement: GitHub Releases SHALL preserve release-it's changelog body
The CI workflow SHALL NOT pass a `releaseBody` parameter to tauri-action, allowing the GitHub Release body created by release-it (containing the generated changelog) to remain unchanged when build artifacts are uploaded.

#### Scenario: Release body contains full changelog
- **WHEN** a release is published and build artifacts are uploaded
- **THEN** the GitHub Release body contains the full changelog generated by release-it, not a placeholder message

### Requirement: CI build matrix SHALL use ubuntu-24.04
The Linux build runner in the CI workflow SHALL use `ubuntu-24.04` instead of `ubuntu-22.04`.

#### Scenario: Linux build runs on Ubuntu 24.04
- **WHEN** the build job runs for the Linux platform
- **THEN** the runner is `ubuntu-24.04`

### Requirement: CI SHALL pin pnpm to major version 9
All CI workflow steps that install pnpm SHALL use `pnpm@9` instead of the latest version.

#### Scenario: pnpm is installed with pinned version
- **WHEN** the CI workflow installs pnpm
- **THEN** the command is `npm install -g pnpm@9`

### Requirement: Script paths SHALL be updated in all references
The `.release-it.json` hook and `.github/workflows/release.yml` SHALL reference the new script paths under `scripts/deploy/`.

#### Scenario: release-it hook points to new path
- **WHEN** release-it runs the `after:bump` hook
- **THEN** it executes `node scripts/deploy/sync-versions.js`

#### Scenario: CI workflow points to new path
- **WHEN** the update-manifests job runs
- **THEN** it executes `node scripts/deploy/update-sha256.js --from-artifacts sha256-artifacts`
