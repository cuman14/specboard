🏗️ Architecture

System architecture, IPC contract, and design principles for Specboard.

📌 Design Philosophy

Specboard follows a modular architecture with clear separation of concerns. The Tauri Rust backend handles file system operations and CLI subprocess execution, while the React frontend focuses on UI rendering and state management.

🔌 Tauri IPC Contract

Command Input Output Description
open_folder_dialog — string | null Native OS folder picker
read_workspace { path } WorkspaceInfo + Change[] Scan openspec/ structure
read_artifact { path } string Read .md file content
run_openspec_command { cmd, args } { stdout, stderr, exit_code } Run openspec CLI subprocess
watch_workspace { path } — Start FS watcher, emits events
stop_watching — — Stop FS watcher

📏 Design Principles

🔒 KISS Methodology

Keep It Simple, Stupid. Prefer 10-line functions over 50-line "extensible" ones. No over-engineering.

🎯 Minimal State

Prefer derived state over stored state. If local state is sufficient, don't use global state.

🔄 One Way to Do Things

Unify parallel code paths. Don't maintain separate patterns for the same operation.

🗑️ Delete Dead Code

Remove unreachable, unused, or commented-out code. No "just in case" code.

🌐 Cross-Platform Considerations

⚠️ Windows CLI Execution

On Windows, openspec is installed as a .ps1 PowerShell script. Rust Command::new("openspec") cannot execute .ps1 files directly.

Solution: Use cmd /C openspec on Windows to find the .cmd wrapper.

🔥 Vite Watcher Configuration

🚫 CRITICAL: Vite MUST ignore openspec/ folder

When writeArtifact writes to openspec/changes/<name>/tasks.md, Vite's file watcher detects the change and triggers a full page reload, resetting the Zustand store.

Solution: vite.config.ts MUST include **/openspec/** in the server.watch.ignored array.
