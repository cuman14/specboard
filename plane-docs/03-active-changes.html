📌 What are Changes?

In OpenSpec, a Change is a feature, fix, or modification tracked via artifacts: proposal.md, specs.md, design.md, and tasks.md.

🎨 transparent-logo-background

Status: In Progress

Why

The current Specboard icons have an opaque background that causes visual issues on both Windows and macOS. A transparent background is the standard for application icons across all platforms and ensures the logo renders cleanly against any surface color.

What Changes

  • Regenerate all icon assets in src-tauri/icons/ with transparent backgrounds
  • Update the icon generation script to produce transparent-background icons from a source SVG/PNG
  • Ensure the Windows .ico contains a 32x32 entry with alpha transparency
  • Verify macOS .icns preserves alpha channel across all resolutions

New Capabilities

Capability Description
transparent-icon-generation Generate all platform icons from source with transparent background, ensuring correct alpha handling per format

🍺 homebrew-crossrepo-push

Status: In Progress

Why

The current release workflow uses a manual git clone with an embedded PAT token URL to push the Homebrew Cask file. This approach is fragile, hard to audit, and exposes the token in the CI log context.

What Changes

  • Replace manual clone with actions/checkout@v4 using explicit token parameter
  • Remove the separate "Verify access to tap before clone" step
  • Use a dedicated path for checkout to keep it isolated

New Capabilities

Capability Description
homebrew-crossrepo-push Replace manual git clone with actions/checkout for pushing Cask updates to external Homebrew tap repository

🚀 automated-releases-with-conventional-commits

Status: In Progress

Why

Currently, creating a release requires manual steps: update version numbers in multiple files, create a Git tag, and push it. This is error-prone and inconsistent. By automating the release process based on conventional commits, we eliminate manual version management and ensure consistent, semantic versioning.

What Changes

  • Add semantic-release workflow — New GitHub Actions workflow that analyzes conventional commits on every push to main
  • Automatic version bumping — Detects feat:, fix:, and BREAKING CHANGE: commits
  • Automatic Git tag creation — Creates and pushes version tags (v*) automatically
  • Conventional commit enforcement — Add commitlint to ensure all commits follow the conventional format
  • Automatic changelog generation — Generate CHANGELOG.md from commit history

New Capabilities

Capability Description
semantic-release-automation GitHub Actions workflow that detects version changes from conventional commits, bumps versions, creates Git tags
conventional-commit-enforcement commitlint configuration and CI check ensuring conventional commit format
auto-changelog-generation Automatic generation of CHANGELOG.md following Keep a Changelog format

🖼️ update-tauri-window-icon

Status: In Progress

Why

The Tauri app window currently shows the default Tauri icon in the Windows taskbar and title bar instead of the Specboard logo. This breaks brand consistency and makes the app harder to identify among open windows.

What Changes

  • Replace the default icon.ico in src-tauri/icons/ with a Specboard-branded .ico file
  • Update tauri.conf.json bundle.icon list to reference the correct icon file
  • Ensure the window taskbar icon, title bar icon, and tray icon all show the Specboard logo

Impact

  • src-tauri/icons/icon.ico — replaced with Specboard-branded icon
  • src-tauri/icons/icon.png — replaced with Specboard-branded PNG
  • src-tauri/tauri.conf.json — bundle.icon may be updated
  • No API or logic changes — purely visual/asset change
